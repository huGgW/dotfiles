# Project Architect 평가 안내

이 평가 세트는 스킬 변경의 행동 회귀를 확인하는 실행자와 독립 평가자를 위한 참조입니다. `evals.json`은 기존 `id`, `prompt`, `expected_output`, `files`, `expectations` 구조를 유지하며 총 23개 사례를 담습니다. 기대 조건은 행동 검증 기준이지 실행 결과가 아닙니다.

## 실행 입력 준비

- `files` 경로는 **스킬 디렉터리 기준**입니다. 예: `evals/fixtures/source-delta/design/plan.md`.
- 각 실행은 별도 임시 프로젝트 루트에서 시작합니다. `evals/fixtures/<case>/` 다음의 상대 경로를 보존하여 나열된 파일을 복사합니다. 저장소의 실제 fixture는 수정하지 않습니다.
- eval 21은 기존 로그와 소비 계약의 조합입니다. 서로 다른 fixture 디렉터리에서 입력을 가져오되 위 규칙으로 하나의 실행 루트에 병합합니다. 대상 경로 충돌은 없습니다.
- `files: []`인 사례는 빈 프로젝트에서 실행합니다. 대화 전용 사례는 최종 응답과 도구 기록을 보관하고 파일 생성 여부도 확인합니다.
- 사용자 프롬프트, 초기 입력, 도구 권한, 보조 스킬 가용성은 구버전/신버전 실행에서 같아야 합니다. 대상 `project-architect` 버전만 달리합니다. 각 실행의 출력과 기록은 독립적으로 보관합니다.
- 파일 수정은 프롬프트의 승인 범위 안에서만 수행합니다. 외부 게시, 코드 구현, fixture 코드 실행은 평가의 기본 전제가 아닙니다. eval 9도 테스트를 읽었다는 사실과 실행했다는 사실을 구분합니다.

## 우선 비교할 세 사례

| ID | 입력 fixture | 비교할 핵심 행동 | 확보할 증거 |
| --- | --- | --- | --- |
| 14 | `scoped-readiness/` | 수동 replay만 준비도 판단 후 독립 retention 의제로 전환. 전체 컴포넌트/Phase 완료를 요구하지 않고 명명·소유권·불변조건을 질문 | 최종 대화, 입력 읽기 기록, 파일·티켓 미생성 |
| 15 | `source-delta/` | 외부 반복 제안 중복 방지, 새 관측/제안 구분, 권한 있는 회의 timeout 합의만 부분 반영. 기록·채택·구현·검증 구분 | 기존 external 참조와 계약/체크포인트 diff, 새 meeting 문서, 원문 보존, 도구 기록 |
| 16 | `draft-review/` | 미선택 후보로도 요청한 리뷰 초안을 생성. 합의/현재 구현을 꾸미지 않고 output과 private source map 모두 최소 OKF 적용 | 두 출력 파일, 원본 보존, YAML/누출 확인, 도구 기록 |

이 세 사례는 **실행 후보**입니다. 정적 검증이나 사례 작성만으로 구버전 실패·신버전 통과 또는 개선율을 주장하지 않습니다. 프롬프트 자체도 일부 경계를 명시하므로 구버전이 통과할 수 있습니다. 실제 출력의 차이와 실패 근거를 보고하며 차이가 없으면 그대로 기록합니다.

## 판정과 한계

- 파일 diff와 도구 기록을 함께 확인합니다. 최종 응답의 자기 보고만으로 미게시·미구현·검증 완료를 인정하지 않습니다.
- 새로 작성한 관리 문서는 루트 종류와 무관하게 YAML frontmatter를 확인합니다. 비어 있지 않은 `type`, 기본 `title`/`description`, 미검토 초안의 `status: draft`, 새 legacy timestamp frontmatter 필드/`#Citations` 부재, 조건에 맞는 진실한 provenance를 확인합니다. 진실한 `generated.at`/`verified.at`은 허용하며, 공유 문서의 metadata도 내부 경로 누출 점검 대상입니다.
- 기존 fixture의 v0.1 frontmatter와 timestamp, legacy Phase 경로는 의도적인 회귀 입력입니다. 평가 준비 중 마이그레이션하지 않습니다. 기존 무메타데이터 output도 작은 수정 때문에 전면 변환하도록 강제하지 않습니다. 원문 `.txt`는 관리 문서로 변환하지 않습니다.
- `index.md`와 `log.md`는 예약 탐색/변경 문서이므로 일반 concept metadata를 강제하지 않습니다. 모든 디렉터리 index, 모든 root, 별도 option 파일, 삼중 기록을 보편적 성공 조건으로 사용하지 않습니다.
- 표현은 내용과 독자 적합성을 평가합니다. 사용자가 요구하지 않은 정확한 표/다이어그램 수, 단어 수, humanizer 강제 실행은 판정 기준이 아닙니다. 명시적으로 요청한 Mermaid/Python 예시는 여전히 확인합니다.
- 의미 있는 delta·소유권·준비도·내용 보존은 의미 기반 판정이 필요합니다. JSON 파싱과 경로 존재 확인은 실행 준비의 증거일 뿐 행동 통과 증거가 아닙니다.
- 이 파일은 평가 정의와 실행 지침이며 실행 결과가 아닙니다. 실제 실행 범위, 독립 판정, 벤치마크와 한계는 각 실행 workspace의 결과로 확인합니다.
